# mossyleaf.studio — project guide for Claude

Showcase site and shop of the mossyleaf.studio illustration studio (sketchbook look: watercolor leaves, washi tape, paper cards) with an admin to edit every section. The shop is **closed** until the studio clicks « Publish » in the admin: then `/` leads to the shop (English and French, `/{en,fr}/…`) and « Show the growing note » closes it again. While closed, `/` serves the English-only growing note. Admin UI in **English and French**. URLs, code, commits: **English**.

Architecture and conventions mirror `~/Sites/mossyleaf-studio/mossydew` (read its `CLAUDE.md` when in doubt).

## Code style

- **Never write comments** — no docblocks, no inline `//`/`#`, no `<!-- -->`, no `{# #}`. Only type-only PHPDoc the type system needs is allowed.
- **SOLID in every layer**: one use case per handler, one route per controller, one exception per file.

## Stack

- Symfony 8.1, PHP 8.5 (FrankenPHP, with GD for images), Doctrine ORM 3, PostgreSQL 18, ULIDs.
- Vue 3 + Vite through `pentatrion/vite-bundle`, four entries: `site` (the note at `/`), `shop` (the shop pages), `admin` (SPA with vue-router under `/admin`), `auth` (sign-in error page).
- Tests: PHPUnit 13 (unit + functional, DAMA rollback), Vitest, Playwright.

## Running things (always in Docker)

```bash
make up              # php + database + node (Vite :5175) + mock mossyleaf accounts (:8093) + Mailpit (:8095) → http://localhost:8094 (admin on /admin)
make db              # create + migrate dev DB
make fixtures        # reset the content to the starting texts and links
make test / test-js / phpstan / deptrac / cs / cs-fix   # keep all at 0
make e2e             # Playwright against php-e2e (APP_ENV=test)
make shots           # screenshots of the site and the admin in e2e/shots/
make ci             # full suite from a fresh checkout, as GitHub Actions runs it
make deploy         # run the image CI published to Docker Hub for HEAD on DEPLOY_HOST (.deploy.env)
```

## Backend (Onion) — `src/`

Contexts: `Identity` (accounts), `Sales` (`ShippingZone`: `france`, `eu`, `world` with price, optional free-from amount, on/off, seeded off by migration; a country belongs to one zone: FR and MC to `france`, the other EU member states to `eu`, the rest to `world`; `CartPricer` is the only code that prices a cart, orders go through it), `Content` (`SiteText` single row, `Link`, `Artwork`) and `Catalogue` (`Product`, `ProductVariant`, `ProductPhoto`, `Category`, pushed by mossytrunk through `PUT /integrations/catalogue`, which first reads `GET /integrations/orders` (the sales, see Orders and payment); a pushed product may carry `descriptions` (`{"fr": …, "en": …}`, plain text), which fill only a language whose description is empty (`Product::prefillDescription`, cut to `MAX_DESCRIPTION` at the last paragraph break, else sentence end, else space), so what the studio wrote is never overwritten; the admin edits only the website side: French and English title and description, slug, visibility, order, photos, category labels; `CatalogueQueries` is the read side). `Ordering`, `Orderable` and the order/text exceptions live in `Domain\Shared`. Same layers and rules as MossyDew: Domain has no dependencies, Application holds use cases `<Context>/<UseCase>/{Command, Handler}`, views and ports (`ArtworkStorage`, `ImageResizer`, `Transaction`), Infrastructure the Doctrine repositories, `LocalArtworkStorage` (`var/share/artworks`) and `GdImageResizer` (WebP, 1600 px max), Presentation the controllers.

- **Open rule, draft and publication**: every admin edit changes the draft. `PublishSite` freezes the draft `SiteView` as JSON in `PublishedSite` (single row: the page shown, `content` for the note, `shop_content` for the shop texts, links, logo, fonts and legal pages, and the media files they use). **The shop is open exactly when the published page is `full` and the row carries `shop_content`** (`PublishedSite::opensShop()`, read through `ContentQueries::shopIsOpen()`, the only place that answers); there is no flag or setting. Publishing the note (`page: note`) closes it, publishing `full` opens it or refreshes the frozen texts. `PublicPage::Full` is only a stored value: the old single full page is gone, nothing renders it and `published_site.content` is still frozen as before. What waits for « Publish »: studio texts, links, logo, fonts, images, legal pages. What is live at once: products, photos, conventions, shipping zones, stock. `/` (`HomeController`): closed, the growing note (`note-visual.spec.js` and its baselines guard its look); open, a 302 to `/fr/` or `/en/` by `Accept-Language` (English by default) with `Vary: Accept-Language`, no cookie, no session. Previews for editors only (noindex, no-store, draft banner): `/beta/` is a 302 to `/beta/{en,fr}/` (the shop draft), `/beta/note/` previews the note (`BetaNoteController`). The banner links come from the props (`layout.draft`) or the `data-shop`/`data-note`/`data-admin` attributes of the note preview, built by `ShopUrls`: no preview address is written by hand in the front, and the publication JSON carries `open` and `preview {shop: {en, fr}, about: {en, fr}, note}`. `MediaSweeper` deletes an image file only when neither the draft nor the published snapshot uses it: never delete media files directly. Product photos (full and thumb, stored through `ArtworkStorage`) are live and belong to no draft: the sweeper keeps every file listed by `ProductRepository::photoFiles()`.
- **Legal pages and conventions**: `LegalPage` (four rows keyed by `LegalKind`: terms, legal-notice, privacy, shipping-returns; text per language, 30 000 characters) follows the draft: the admin edits it, `/beta` previews it, `PublishSite` freezes it into `published_site.shop_content` (`ShopContentView::$legal`). `Convention` is live, no draft: upcoming means `endsOn` today or later (Europe/Paris, through the clock); the shop never lists past ones, the admin lists all. A legal page empty in both languages is a shop 404 and leaves the footer; French and English fall back on each other. Shop routes `shop_conventions` and `shop_legal`; admin `/admin/conventions` (Shop group) and `/admin/legal` (Site group).
- **Cart**: `POST /api/shop/{_locale}/quote` (`api_shop_quote`, also under `/beta`; door, body guard, stateless, 60 per minute per address) answers the `CartPricer` quote for `{lines: [{sku, quantity}], country}`; the page `shop_cart` (`/{_locale}/cart`, noindex) lists the deliverable countries. The cart lives in `localStorage` (`mossyleaf.cart`, no cookie, no session) through `assets/vue/site/cart.js` (pure) and `useCart.js`, provided in `ShopApp`; `shipping.js` holds the country and shipping-state helpers. Shipping zones are edited live at `/admin/settings` (`/api/admin/shipping-zones`). Fixtures turn the three zones on.
- **Text blocks of a legal page**: `## ` heading, blank line between paragraphs, consecutive `- ` lines a list, `[label](https://…)` an inline link. Two parsers with the same cases: `App\Application\Content\TextBlocks` (PHP, prerender, Twig filter `rich_blocks`) and `assets/vue/site/richBlocks.js` (rendered by `RichBlocks.vue`), both tested against `tests/Fixtures/rich-blocks.json`. Date ranges are formatted by `assets/vue/site/dates.js` and `DateRangeExtension` (Twig `date_range`), both tested against `tests/Fixtures/date-ranges.json`. Demo conventions and placeholder legal texts: `fixtures/ShopContentFixtures.php`.
- `templates/site.html.twig` writes the SEO head (title from `pageTitle`, canonical, Open Graph, Twitter card, JSON-LD) and `site/_prerender.html.twig` the content as plain HTML for crawlers; Vue replaces it on load, so both must show the same content. `robots.txt` and `sitemap.xml` are controllers. Uploaded images are served by `MediaController` (`/media/artworks/{ulid}.webp`, immutable cache).
- Admin API under `/api/admin/…` (texts per section, links, artworks, and `products`, `products/{id}`, `products/{id}/visibility`, `products/order`, `products/{id}/photos[/{photo}|/order]`, `categories`, `categories/{id}`, `categories/order`, one controller per route in `Presentation/Api/Catalogue`), `MapRequestPayload` DTOs, domain exceptions → 422 `problem+json`.
- **Shop door and previews**: `src/Presentation/Web/Shop/` holds one controller per page, routes `shop_*` at `/{_locale}/…` (`en|fr`), imported a second time under `/beta` as `beta_shop_*` with `preview: true` (editors only). `ShopDoor::admits($preview)` is `$preview || shopIsOpen()`: while closed every public shop page answers 302 to `/`, the public API 404, an unknown order address 302 to `/`, and only the page and status route of an existing order (`ShopDoor::EXEMPT`) keep answering. Open, public pages read the frozen `ContentQueries::shop(false)` plus the live catalogue, conventions and zones; they show no hidden product, no draft text and no banner, and their props carry no `preview`, `hidden` or `draft` key. Each indexable public page has an `ETag` (xxh128 over the rendered HTML, so a new build or label changes it; 304 on a match, `public, max-age=0, must-revalidate`); cart and checkout are `noindex`, the order page `private, no-store`, preview pages `private, no-store, noindex`. `ShopUrls` is the only place that builds shop URLs: Twig and Vue get every link through the props. `ShopPage::render()` writes `{layout, data}` into `#site-content` and the `seo` variable for `templates/shop.html.twig` (prerender in `templates/shop/`). `ContentQueries::shop(bool $draft)` reads the draft, or the frozen `shop_content`. Interface labels live in `assets/vue/i18n/{en,fr}/site.json`, read by Vue (`vue/site/i18n.js`) and by Twig (`site_t`).
- **SEO while open**: `sitemap.xml` lists, in both languages with `fr`, `en` and `x-default` (English) alternates, the home, the listing, every visible product, conventions, about, contact and each legal page with text (never cart, checkout or an order); closed it lists `/` alone. `robots.txt` adds `Disallow: /{en,fr}/order/` while open. The shop home carries the `Organization` and `WebSite` JSON-LD (`StudioSeo`). A listing filtered by `?category=` keeps the canonical and alternates of the plain listing and its language switch keeps the filter; `shop` is current in the navigation on the listing and on product pages.
- **Readiness**: `GET /api/admin/shop/readiness` (`ShopReadiness::check()`) answers `{ready, items: [{key, state, count}]}`, `state` being `ok`, `blocker` or `warning`, keys in order: `identity` (studio name), `payment` (`PaymentGateway::isReady()`), `mail` (`StudioMailbox::isOpen()` and a real transport: `MAILER_DSN` unset, empty or `null://` is a blocker), `shipping` (a zone on), `products` (one on sale), `terms`, `legalNotice`, `privacy` (text in any language; blockers), `shippingReturns` (warning), `photos` (warning: products on sale without photo), `mossytrunk` (warning: `MOSSYTRUNK_TOKEN` unusable), `testOrders` (warning: test orders still holding units). `ready` means no blocker. `PublishSiteHandler` refuses `full` while a blocker stands with `ShopNotReady`: 422 problem+json, `code` `content.shop_not_ready`, `blockers` the keys; publishing the note is always allowed. The admin shell preloads the readiness with the publication; `PublishBar` shows the state, the items that are not ok with how many are ready, and the two buttons. The publication JSON carries `open` and the preview URLs (`preview.shop.{en,fr}`, `preview.about.{en,fr}`, `preview.note`): the admin never writes a `/beta/` address.
- **Shop pages**: `shop_listing` (`/{_locale}/shop`, optional `?category=<key>`, the key being the lower-case slug of the mossytrunk category name in the same locale whatever the page language, or the category ULID when that slug is empty or taken) and `shop_product` (`/{_locale}/shop/{slug}`); the home also carries the latest eight products and the category tiles. A product is *listed* when it is not retired and its price is above 0; the public also needs it visible, the preview adds hidden ones flagged `hidden`. An unknown category, an unlisted or retired product answers the shop 404. Title: website title in the page language, else the other language, else the mossytrunk `displayName`; category label: same chain ending on `name`. `CatalogueQueries::shop()/shopProduct()/related()` return `ShopProductView`; stock is computed only in `ShopVariantView::of` (`available` capped at 10, never the exact stock, and `state` `inStock`/`lastPieces` (3 or fewer)/`soldOut` that Twig and Vue both print). Prices travel as integer cents: Vue formats them with `assets/vue/site/money.js` (`Intl.NumberFormat`, EUR, page language) and the prerender with the Twig `money` filter, which gives the same output. The buy box emits `add` and shows its button only when a cart is provided.
- **Public API of the shop**: controllers in `src/Presentation/Api/Shop/` (one per route, `api_shop_*` at `/api/shop/{_locale}/…`, `stateless: true`), imported a second time under `/beta` as `beta_api_shop_*` (`preview: true`, session, editors only). `security.yaml` has a `PUBLIC_ACCESS` rule for `^/api/shop/` before `^/api/`. `ShopApiDoor` answers 404 problem+json on these routes while `ShopDoor` is shut and `ShopApiNotFoundListener` turns any `NotFoundHttpException` into the same (and a 405 on `/api/shop/…` while the door is shut); `ShopApiBodyGuard` refuses a body over 64 KB with 413 `problem.too_large` before it is parsed; `ProblemResponse` takes an optional `code` (message key of the domain exception, `problem.not_found`, `problem.too_many_requests`). `SameOriginGuard` covers `/api/` and `/beta/api/` on the URL-decoded path; `/integrations/…` keeps `IntegrationGuard`.
- **Rate limits** (`config/packages/rate_limiter.yaml`, fixed window, cache storage, `lock_factory: null`, keyed on the client address): `contact` 5 per hour, `quote` 60 per minute and `checkout` 10 per 10 minutes (429 `problem.too_many_requests` with `Retry-After`), `integration_authentication` 10 failed tokens per minute (429 before the token is compared), `order_status` 20 payment verifications per minute (beyond, the page and the status route answer the stored state without asking SumUp) and `webhook` 60 per minute (beyond, still 204, nothing verified). The test and e2e cache is an array pool reset per request, so PHPUnit proves limits by pre-consuming `limiter.*`; e2e cannot reach a 429.
- **Contact**: `POST /api/shop/{_locale}/contact` (`SendContactMessage` use case, `ContactMailboxDoor` answers 404 before validation when the mailbox is closed, email validated in strict mode like `Mime\Address`, `StudioMailbox` port, `MailerStudioMailbox` plain-text mail, nothing stored, honeypot `website` answers 204 without sending); page `shop_contact` (`/{_locale}/contact`). Mail goes through `symfony/mailer` synchronously: `MAILER_DSN` (unset or empty means `null://null`) and the mailbox is open only when `MAILER_FROM` and `STUDIO_EMAIL` are both set (`MailAddresses::isOpen()`); closed, the route answers 404 and the page offers no form. The shop cannot open without a real transport either (readiness item `mail`). Dev and e2e send to Mailpit (`smtp://mailpit:1025`, web UI on `MAILPIT_PORT`, default 8095; `php-e2e` and `playwright` depend on it); PHPUnit uses the Symfony mailer assertions.
- Inline links in texts are written `[label](https://…)` and rendered by `assets/vue/site/richText.js` (never `v-html`).
- Text limits live on the entities (`SiteText::MAX_*`, `Link::MAX_*`, `Artwork::MAX_ALT`, `Product::MAX_*`, `Category::MAX_LABEL`) and are mirrored in `assets/vue/admin/limits.js`.
- Fonts: the admin types any Google Fonts family per `FontRole` (heading, body); empty means the bundled Kalam 700 (headings) / Quicksand Variable 500 (text). `ChooseFont` asks `FontLibrary` (`GoogleFontLibrary`: CSS2 API for the faces, `fonts.google.com/metadata/fonts` cached a day for the names and autocomplete) for the closest weight in latin + latin-ext, and `LocalFontStorage` self-hosts it (`var/share/fonts`, `/media/fonts/{ulid}.css` + woff2, swept like the images): visitors never contact Google. `site.html.twig` links the stylesheets and sets `--font-display(-weight)` / `--font-body(-weight)` on `<html>`. Tests fake Google with `Tests\Support\FakeGoogleFonts`.

## Orders and payment (Sales)

- `Order` (`shop_order`, lines in `shop_order_line`, no foreign key to the catalogue) has a `reference` (`ML-XXXX-XXXX`, also the SumUp `checkout_reference`), a 43-character `token` (the only key of the status page), a `test` flag and amounts in integer cents. States: `pending`, `paid`, `shipped`, `failed`, `expired`, `cancelled`; `OrderStatus::allows` is the machine (a verified payment also moves `failed`/`expired` to `paid`). Shipping and cancelling are done in the admin (see Orders in the admin).
- Stock: `ShopVariantView::of` is the single spot, available = stock minus units on pending orders not past `expiresAt` (35 minutes). Placing an order locks the catalogue, checks again and writes no stock; stock is taken only when the order becomes paid, never below 0: each order line records in `taken` what its variant really gave (`ProductVariant::take` returns it; 0 when the sku has no variant). Failed and expired orders restore nothing. Every read of stock under `ProductRepository::lock()` goes through `variantsWithSkus()`, which refreshes the variants from the database (never a copy already in the EntityManager).
- `PlaceOrder` prices through `CartPricer`, commits the pending order, then opens the checkout at the gateway outside the transaction (`PaymentUnavailable` makes the order `failed`; `CartOutdated` when the total shown differs). `ConfirmPayment` is the only way to paid: it asks the gateway, locks the order, checks state, reference, amount and EUR, takes the stock, then sends the two mails once.
- `PaymentGateway` port, adapter `SumUpGateway` (HttpClient, hosted checkout) with `SUMUP_API_KEY` and `SUMUP_MERCHANT_CODE`; empty means not ready: no checkout link, checkout routes 404, the rest works. `POST /webhooks/sumup` is unsigned and only a trigger (runs `ConfirmPayment` for that id, always 204). The order page and its status route also verify (`OrderQueries::paymentToVerify`, limiter `order_status`) a pending order, and a failed one with a checkout until its `expiresAt` (a declined card can be retried on the same SumUp page), and are exempt from the shop door. `SumUpGateway::find` gives up after 5 seconds without an answer and 8 seconds in all (`open` keeps 10 and 20), so the settle before `GET /integrations/orders` stays well under the 20 seconds mossytrunk waits.
- Orders placed through `/beta/…` are test orders: same behaviour, labelled on the status page and in the mail subjects.
- Mail: `MAILER_FROM` is the sender of every mail, `STUDIO_EMAIL` the studio inbox; nothing leaves unless both are set. On paid: confirmation to the customer (order language, Reply-To the studio) and notice to the studio (French, Reply-To the customer). A failing mail is logged without personal data and never undoes the payment.
- **Sales pulled by mossytrunk**: `GET /integrations/orders` (`Presentation/Integration/ListOrdersController`: `SettleStaleOrders` first, so a payment the site missed is verified before the sales leave and SumUp being down never stops the export, then `ExportOrdersHandler`) answers `{"orders": [{"id", "reference", "placedAt", "lines": [{"sku", "name", "variant", "unitPrice", "quantity"}], "goods", "shipping", "cancelledAt"}]}`: every non-test order in `paid`, `shipped` or `cancelled`, oldest first (`createdAt`, then id), `id` and `reference` both the order reference, dates ISO 8601 with offset, amounts in integer cents, `name` the mossytrunk display name of the line, nothing personal. In one transaction it locks those orders (`OrderRepository::lockSold()`) and stamps `exportedAt` with the clock on the ones sent for the first time (`Order::export()`, never changed afterwards). The catalogue push, under the catalogue lock, serves from the pushed stock of each sku the lines of the paid or shipped orders (test orders included) whose `exportedAt` is null, oldest order first (`OrderRepository::unexportedLines()`): each line's `taken` becomes what the push could subtract for it and the stock written is what is left, so `max(0, pushed - units)`. mossytrunk already counts what it read, not what was paid since. Cancelling an order (`CancelOrder`) or deleting a paid test order (`DeleteTestOrder`) gives back its `taken` and takes the order out of the lines served, so the push stops subtracting it; an order cancelled after its export comes back with its `cancelledAt` at the next export. Known limits: an order mossytrunk reads but leaves « à associer » is stamped all the same, so neither side counts its units until the studio links it in mossytrunk (link waiting orders before publishing again); a paid or shipped test order is never exported, so it is subtracted at every push until it is cancelled or deleted; the answer holds every sold order ever and mossytrunk refuses one over 5 MB (roughly 12 000 orders), which would stop every publication.
- Tests fake SumUp with `Tests\Support\FakeSumUp` (decorates `http_client`, one JSON file per checkout in the share dir) and a test-only hosted page `/_fake/sumup/{id}` (Pay, Decline, Back to the shop; `?webhook=0` skips the webhook). `e2e/tests/checkout.spec.js` drives it with Mailpit.
- **Orders in the admin**: `/admin` and the sign-in landing open on `/admin/orders` (first of the Shop group; list with tabs To ship, Shipped, Other, search; `/admin/orders/{id}` one order; `useOrders.js`, pure `orders.js`). Routes `api_orders_{list,ship,cancel,check_payment,delete}` in `Presentation/Api/Sales/` (`GET orders`, `POST orders/{id}/shipment|cancellation|payment-check`, `DELETE orders/{id}`), one controller each, 422 `sales.order_move_refused` for a move `OrderStatus::allows` refuses. `ShipOrder` (paid only; optional tracking number, at most 64 characters on one line) mails the customer after the commit (`OrderMails::shipped`, a failing mail is logged and never undoes the shipment); `CancelOrder` (paid or shipped) sends no mail and never refunds: refund in the SumUp dashboard first. Cancelling, and deleting a paid or shipped test order, give the units back through `OrderStock` (`stock += taken` per sku still in the catalogue, under `ProductRepository::lock()`): never more than the order took. `DeleteTestOrder` refuses an order that is not a test order (`sales.not_a_test_order`) and a pending one whose checkout can still be paid (`Order::canBePaidAt`, `sales.checkout_still_open`). `CheckPayment` runs `ConfirmPayment` for one order with a checkout (503 `sales.payment_unavailable` when SumUp is down). `SettleStaleOrders` runs at the start of `GET /api/admin/orders` (and of the admin shell preload, and of `GET /integrations/orders`): at most 20 gateway calls and no new call once 5 seconds have passed, pending orders past `expiresAt` verified then expired or failed, unpaid orders older than 14 days verified once more then deleted, stopping quietly at the first `PaymentUnavailable` (`SumUpGateway::find` reads a 404 as an expired checkout, so a checkout SumUp forgot never blocks the run). The status JSON ends with `trackingNumber` (null unless shipped). e2e ages an order with the test-only `POST /_fake/orders/{reference}/expire`; shared helpers in `e2e/tests/support/orders.js`.

## Accounts & security

- Sign-in = mossyleaf accounts (Authentik at `accounts.mossyleaf.studio`, project `~/Sites/mossyleaf-studio/accounts`), OIDC code flow + PKCE, same classes as MossyDew. Only accounts whose `groups` claim contains `OIDC_REQUIRED_GROUP` (`mossyleaf-studio`) get in; dev leaves it empty.

- `/` (note, or 302 to the shop), `/media`, `/robots.txt`, `/sitemap.xml` and, once the shop is open, its pages and `/api/shop/` are public and start no session; `/admin`, `/beta` and `/api/` need `ROLE_USER`.
- The admin shell (`AppShellController`, `/admin/…`) preloads API answers into its HTML, customers' names and addresses included, and answers `Cache-Control: private, no-store`.

- **Navigation**: shop pages change through Turbo Drive (`@hotwired/turbo`, imported only by `shop.js`; the note and the admin never load it). `turbo:before-render` unmounts `ShopApp`, `turbo:render` mounts it again on the new `#site-content` (also for cache restores and the shop 404), resets `<html lang>` and the font `style` of `<html>` (Turbo copies neither), moves focus to `#shop` (its `tabindex` goes on blur) and writes the title into the permanent `#shop-announcer` 150 ms later, so screen readers hear it. Pages with timers or pending requests stop them on unmount (`active` flag in `OrderPage` and `CheckoutPage`). The cart is one `useCart()` per document, given with `app.provide('cart', …)`; read URL state in `setup()`, never at module level. `turbo-cache-control: no-preview` keeps snapshots for back and forward only, `no-cache` on the order page and the checkout so back fetches them again; the entry tags are `data-turbo-track="reload"`, so a deploy, the admin, the note and its preview load as full documents; JSON-LD sits in the body because Turbo never removes head scripts. Loading bar: `assets/vue/site/progressBar.js` (mossytrunk's timings, shop tokens; Turbo's own bar hidden). Full loads are marked `data-turbo="false"` (the order page Pay pill, towards SumUp, and the checkout link to the order page, so its `Referrer-Policy: no-referrer` applies); the checkout sends an empty cart to the cart with `location.replace`; ahead-fetch on hover is off (`data-turbo-prefetch="false"`) on the cart's checkout pill. Spec `e2e/tests/navigation.spec.js`.
- The shop never imports `composables/useApi.js`: it posts through `vue/site/api.js` (`postJson`, throws `ApiError` from `composables/apiError.js` with `status`, `code`, `violations`). Shared shop form pieces: `SiteField`, `Notice`, `contactForm.js`, labels `form.*` in `site.json`.
- **Bulk actions** (admin lists): every list has a checkbox per row (`SelectCheck`, named after its item), one in the head that ticks what is visible (mixed state), and `BulkBar` (over the ui `SelectionBar`, sticky at the bottom; Escape and Deselect clear). The selection is `useSelection(visibleItems)` over the pure `assets/vue/admin/selection.js` (it drops what leaves the visible list; Escape is ignored behind a dialog, in a field, a list box or a toast); the run is `useBulk` over the pure `bulk.js` (`planBulk`, `runBulk`, `bulkMessage`): one item after the other, ending with ONE toast (done, skipped and why, refused with the first reason); failed items still in the list stay ticked, the rest is cleared. One run at a time for the whole admin (`bulkProgress`, module state in `useSelection.js`): while it runs every selection, drag, move, edit, delete and visibility switch of the lists is disabled, and a list opened meanwhile shows the running bar; afterwards focus goes back to the bar, or to the first checkbox of the list when nothing is left ticked. A page only declares `{key, label(count), skip?, perform, done, confirm?, tone?}` per action, where `perform` is the existing single-item composable call (no bulk route, every server rule applies per item), and `confirm` opens a confirmation with the numbers. Actions: products show / hide (retired skipped, no confirmation), orders mark as shipped (paid only, confirmation counts the mails, no tracking number) and delete (test orders only, pending ones skipped since their checkout can still be paid), links, conventions and images delete; fixed lists (shipping zones, legal pages, categories) and a product's photos have none, and there is no bulk cancel. Spec `e2e/tests/bulk-edit.spec.js` guards it.
